# Lucid Dream

[![CI](https://github.com/momonanq/lucid-dream/actions/workflows/ci.yml/badge.svg)](https://github.com/momonanq/lucid-dream/actions/workflows/ci.yml)
[![License](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)

Приложение для тренировки осознанных сновидений на связке **Samsung Galaxy Phone + Galaxy Watch**.
Телефон — управляющий клиент и дневник, часы — ночной сенсорный и хаптический модуль.

---

## ⚠️ Что это не

**Это не медицинское устройство.** Приложение не диагностирует стадии сна, не лечит бессонницу,
парасомнии, апноэ или ПТСР и не заменяет консультацию врача или лабораторное исследование сна.

Продукт **не определяет фазу REM** в реальном времени и не утверждает обратного. Исследования
Galaxy Watch показывают лишь умеренную точность классификации стадий по сравнению с
полисомнографией: для Galaxy Watch 3 общая точность четырёхклассовой классификации составила
65.1%, чувствительность REM — около 0.598. Поэтому `confidence` в этом коде — **операционный
показатель для принятия решения о сигнале, а не вероятность REM в научном смысле**. Это различие
принципиально и для честности перед пользователем, и юридически.

Приложение намеренно воздействует стимулами на спящего человека, поэтому фрагментация сна —
реальный вектор вреда. Ограничители описаны ниже и не отключаются из UI.

## Статус

**MVP примерно наполовину.** Архитектура, алгоритмы и нативный слой готовы; интеграция с
реальными сенсорами Samsung — нет.

| Что | Состояние |
|---|---|
| Алгоритмы (скоринг, решение о сигнале, калибровка, гардрейлы) | ✅ Готово, 50 тестов |
| Android-приложение (Compose Material 3) | ✅ Экраны Tonight, Dream Journal, Sleep Review |
| Wear OS-приложение (Wear Compose) | ✅ Ready, Night Running, Morning Feedback |
| Транспорт телефон↔часы (Wearable Data Layer) | ✅ С офлайн-очередью и догоном при реконнекте |
| Персистентность (Room) | ✅ Есть |
| Хаптика и аудио-cue | ✅ Реальные `Vibrator` / `AudioTrack` |
| **Samsung Health Sensor SDK** | ⚠️ **Стаб.** Доступ выдаётся по партнёрской заявке, она не подана |
| **Samsung Health Data / стадии сна** | ⚠️ Health Connect + мок с синтетической гипнограммой |
| **Валидация алгоритма** | ❌ **Алгоритм ни разу не видел настоящий PPG** |
| Экран скрининга в онбординге | ❌ Нет — и поэтому ночные сигналы выключены по умолчанию |

> **Важно про метрики.** Пока не пройден пилот на реальных данных, любые цифры «точности
> попадания в REM» измеряют мок, который отдаёт REM ровно там, где алгоритм его ожидает.
> Это самоисполняющееся пророчество, а не результат.

Подробный роадмап, реестр багов и внешние блокеры — в [TASKS.md](TASKS.md).

## Как это работает

### Ночной цикл

1. Телефон отправляет на часы параметры сессии: режим, минимальное окно, интенсивность вибрации,
   лимит сигналов, cooldown.
2. Часы собирают HR, IBI и данные акселерометра, агрегируют их в окна.
3. `RemConfidenceEngine` считает интерпретируемый взвешенный скор — не ML-чёрный ящик:

   | Компонент | Вес | Обоснование |
   |---|---|---|
   | `time_score` | 0.35 | Плотность REM растёт к концу ночи, пик после 4.5 часов |
   | `motion_score` | 0.30 | Мышечная атония в REM даёт длительную неподвижность |
   | `hrv_score` | 0.20 | Автономный профиль REM отличается от глубокого сна |
   | `consistency_score` | 0.15 | Отсекает единичные шумовые окна |

4. `NightCueDecisionEngine` пропускает сигнал только через шесть проверок: достаточность данных,
   минимальное время от засыпания, лимит сигналов за ночь, cooldown после предыдущего,
   персональный порог confidence и подтверждение неподвижности.
5. Утром `CalibrationEngine` сопоставляет сигналы с постфактум-стадиями из Samsung Health и
   адаптирует персональные пороги.

### Гардрейлы против фрагментации сна

Движки выше защищают **одну ночь**. `SleepSafetyGuardian` ограничивает накопление между ночами:

- не более **3 ночей с сигналами** за скользящие 7 дней;
- обязательная **ночь отдыха** между ночами с сигналами;
- **авто-стоп** после 2 ночей подряд, в которых сигналы будили пользователя (wake spike ≥ 50%);
- **авто-стоп** при среднем субъективном качестве сна ≤ 2 из 5 за 3 ночи;
- **скрининг в онбординге**: возраст до 18, апноэ, хроническая бессонница, парасомнии,
  нарколепсия, судорожные расстройства, лечение психотического расстройства.

Сработавший гардрейл **не блокирует приложение**, а понижает ночь до режима `BEGINNER`, где
`NightCueDecisionEngine` независимо подавляет все сигналы. Дневник снов, утренний recall и
reality checks продолжают работать. Двойное исполнение здесь не избыточность: запрет доезжает до
часов, даже если телефон отправит устаревшие параметры сессии.

---

## Режимы

| Режим | Описание |
|---|---|
| `BEGINNER` | Дневник, reality checks, утренний recall. Без ночных сигналов |
| `WBTB` | Мягкий будильник через 4.5–6 часов сна, затем MILD/TLR |
| `TLR` | Предсонное намерение + аудио/вибро-сигнал во время сна |
| `WATCH_ASSIST` | Вероятностные хаптические сигналы по метрикам часов |

Режим WILD в MVP намеренно не включён: он повышает риск тревоги и сонного паралича и размывает
ценностное предложение.

## Архитектура

```
:core:model       чистый Kotlin — модели домена, без Android
:core:algorithm   чистый Kotlin — скоринг, решения, калибровка, гардрейлы
:core:data        Android library — Room, репозитории, транспорт, шлюз Samsung Health
:phoneApp         Android application — Compose Material 3
:wearApp          Wear OS application — Compose for Wear OS
```

Ядро намеренно не зависит от Android: алгоритмы тестируются обычными JVM-тестами за миллисекунды,
без эмулятора и без устройства.

**Стек:** Kotlin 2.1.0, AGP 8.7.3, Gradle 8.14.3, JDK 17, minSdk 30, Compose, Room, Coroutines.
64 исходных файла, 50 тестов.

## Сборка

Нужен Android SDK; путь берётся из `local.properties` или переменной `ANDROID_HOME`.

```bash
./gradlew assembleDebug   # сборка обоих приложений
./gradlew test            # юнит-тесты
./gradlew lint            # статический анализ
```

CI прогоняет эти три шага раздельно и выгружает отчёты lint и тестов артефактом.

## Вклад в проект

Перед изменениями загляните в [TASKS.md](TASKS.md) — там актуальный статус, роадмап M0–M5,
реестр багов и внешние блокеры.

Два правила, специфичных для этого проекта:

1. **Не ослабляйте гардрейлы ради удобства.** Ограничители из `SleepSafetyGuardian` и
   `NightCueDecisionEngine` существуют потому, что код будит спящих людей. Изменение порогов
   требует обоснования, а не только зелёных тестов.
2. **Не выдавайте результаты на моках за валидацию.** `MockSamsungHealthDataGateway` и
   `SamsungSensorDataSourceStub` нужны для разработки, а не для измерения точности.
